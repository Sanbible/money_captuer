# ตรวจสลิปการโอนหลังปิดปาร์ตี้ — design (สั้น)

**ทำไม:** หลังปิดปาร์ตี้ ปุ่ม "โอนแล้ว" ใครก็กดได้โดยไม่มีหลักฐาน อยากให้คนโอนแนบสลิป แล้วระบบ OCR ตรวจยอดเอง

**ตกลงกันแล้ว**
- คนโอน (from) แนบสลิปของรายการโอนนั้น → server อ่านสลิปเอง (ไม่เชื่อยอดจาก browser) → **ยอดต้องตรงเป๊ะ** (ระดับสตางค์) จึงถือว่าโอนแล้ว ขึ้น "ตรวจสลิปแล้ว"
- ยอดไม่ตรง / อ่านยอดไม่ได้ → ไม่ผ่านเลย แสดงยอดในสลิปเทียบกับยอดที่ต้องโอน ให้แนบใบใหม่ (ไม่รวมยอดหลายใบ)
- ตรวจแค่ตัวเลข — ไม่ตรวจชื่อผู้รับ/บัญชี/วันที่
- คนรับ (to) ยังกด "ได้รับแล้ว" เองได้ (เผื่อเงินสด) แสดงว่า "ผู้รับยืนยัน" แยกจากแบบสลิป; คนโอนกดเองไม่ได้อีกต่อไป
- รายการที่ยืนยันด้วยสลิปแล้วยกเลิกไม่ได้
- สลิปหนึ่งใบ (เลขอ้างอิง หรือรูปเดียวกัน) ใช้ยืนยันได้รายการเดียว

**Approaches:** (1) server อ่านสลิปเองใน endpoint ใหม่ ← เลือก เพราะ browser ปลอมยอดไม่ได้; (2) browser อ่านผ่าน /api/slips/read แล้วส่งยอดมา — ปลอมได้ ตัดทิ้ง

**การทำ:** `POST /api/parties/{id}/transfers/{tid}/slip` (multipart) ; SQL `party_pay_with_slip` ตรวจสิทธิ์/สถานะ/ยอด/สลิปซ้ำแบบล็อกแถว ; คอลัมน์ใหม่ `paid_method`, `slip_ref`, `slip_sha256` + unique index ; `party_toggle_paid` ให้เฉพาะคนรับ
